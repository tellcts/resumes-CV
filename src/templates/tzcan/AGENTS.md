# 项目背景
1. 项目采用`TexLive`制作简历模板

# 目录结构
1. `./latexmkrc`作为`latexmk`命令的配置文件，自定义编译行为。
2. `./main.tex`作为编写简历内容的主文件，通过`latexmk main.tex`命令进行编译生成。
3. `./assets/badges/`用于存放校徽图片；`./assets/images/`用于存放个人证件照等。
4. `./styles/components/`存放各类简历模板组件。
5. `./styles/resume-tzcan.cls`作为文档类控制简历的总体结构，并作为导出包提供`./styles/components/`中的所有组件

# 组件生成
1. 项目LaTeX发行版采用`TexLive-2026`，注意语法的版本兼容性。
2. 生成的新组件文件名称统一用`tzcan-*.sty`格式来命名，放在`./styles/components/`目录下，在`./styles/resume-tzcan.cls`通过`\RequirePackage`命令导出。
3. 组件对外提供的接口尽量保持为键值对接口，如果你不确定模块内容结构是否适用键值对接口，请询问用户的意见。
4. 对于被多个组件同时依赖的组件，不要创建新的组件文件，直接在`./styles/components/tzcan-common.sty`追加。
5. 新的命令使用`\newcommand`封装。

# 简历编译
1. 你全程不用执行`latexmk main.tex`命令，全程由用户手动执行编译。

# 文档写作规范
1. 仓库内所有 Markdown 文档（根目录`README.md`、各模板的`USAGE.md`）里的提示框，一律使用 GitHub Alerts 语法，不再使用`> ⚠️`、`> 💡`这类 emoji 前缀的引用块：

   ```markdown
   > [!WARNING]
   > 第一行正文
   > 第二行正文
   ```

2. 五种类型按语义选择，不要按旧 emoji 硬套：

| 类型            | 用在哪里                                                             | 旧的 emoji 写法   |
| --------------- | -------------------------------------------------------------------- | ----------------- |
| `[!NOTE]`       | 补充说明、行为解释、导航入口（「跳到某节」「显示顺序固定」）         | 无 emoji 的引用块 |
| `[!TIP]`        | 省事技巧、推荐做法、捷径                                             | `💡`、`🚀`        |
| `[!IMPORTANT]`  | 不遵守不会报错、但结果不可靠的关键提醒（如装 TeX Live 时未设 A4）    | —                 |
| `[!WARNING]`    | 不遵守就会直接报错或编译失败的硬性约束（如「必须在模板目录下编译」） | `⚠️`              |
| `[!CAUTION]`    | 隐私、数据、安全类负面后果（如把简历上传到第三方服务器）             | —                 |

3. 类型关键字必须是大写英文，写在引用块第一行`> [!TYPE]`；标记行与正文之间不加空行，提示框与前后正文之间各留一个空行。
4. 提示框正文不再写 emoji 前缀（GitHub 会按类型自动渲染图标），需要强调时改用`**加粗**`。
5. 相邻且类型相同的提示框合并为一个；不同主题之间用空 `>` 行分隔。类型不同则保持独立。
6. 提示框内每行都要带`>`前缀，内部可以放列表、代码块和链接，但内容要短；超过一屏的说明写进正文。
7. GitHub Alerts 只在 GitHub 网页端渲染，本地部分 Markdown 预览器会把它显示成普通引用块 —— 这是预期现象，不要为了本地预览好看而改回 emoji 写法。
